A few example skills.

Sketches of the shape a good skill takes — narrow enough to trust, named for what they do, upfront about what they read or run. None of these install from here; they're worked examples for the two notes on writing and installing skills.

documents
pdf-tables. Pulls structured tables out of a PDF and returns them as CSV, instead of a wall of OCR'd text.
web performance
lcp-audit. Runs a Lighthouse pass against a URL and returns the changes with the best time-to-fix ratio, ranked by effort.
agent memory
memory-gc. Walks a long-lived memory file and flags entries past their stated expiry, so stale facts don't silently persist.
testing
flaky-test-finder. Reruns a test suite several times and reports which tests fail intermittently, with the failure rate per test.
deploy
deploy-rollback. Finds the last known-good deploy for a service and prepares the rollback command — it stages the fix, it doesn't run it.
writing
changelog-draft. Turns a range of commits into a changelog entry, grouped by the kind of change rather than by commit message.
data
schema-diff. Compares two database schemas and lists every column that changed type or went missing, before a migration runs.
research
citation-check. Checks that every claim in a draft that cites a source actually matches what that source says.

Why these, specifically

Each one does a single, checkable thing — you can tell from the name alone whether it's the right tool for a task, and from the description alone what it reads or touches. That's the bar from writing a skill your agent will actually use: a trigger specific enough to fire at the right moment, and nothing hidden about what happens once it does.
