A few example skills.

Eight skills from the personal registry referenced in the two notes on writing and installing skills — narrow enough to trust, named for what they do, upfront about what they read or run. Each one installs the same way:

$ skills add <name>
documents
pdf-tables. Pulls structured tables out of a PDF and returns them as CSV, instead of a wall of OCR'd text. $ skills add pdf-tables
web performance
lcp-audit. Runs a Lighthouse pass against a URL and returns the changes with the best time-to-fix ratio, ranked by effort. $ skills add lcp-audit
agent memory
memory-gc. Walks a long-lived memory file and flags entries past their stated expiry, so stale facts don't silently persist. $ skills add memory-gc
testing
flaky-test-finder. Reruns a test suite several times and reports which tests fail intermittently, with the failure rate per test. $ skills add flaky-test-finder
deploy
deploy-rollback. Finds the last known-good deploy for a service and prepares the rollback command — it stages the fix, it doesn't run it. $ skills add deploy-rollback
writing
changelog-draft. Turns a range of commits into a changelog entry, grouped by the kind of change rather than by commit message. $ skills add changelog-draft
data
schema-diff. Compares two database schemas and lists every column that changed type or went missing, before a migration runs. $ skills add schema-diff
research
citation-check. Checks that every claim in a draft that cites a source actually matches what that source says. $ skills add citation-check

Why these, specifically

Each one does a single, checkable thing — you can tell from the name alone whether it's the right tool for a task, and from the description alone what it reads or touches. That's the bar from writing a skill your agent will actually use: a trigger specific enough to fire at the right moment, and nothing hidden about what happens once it does.
